---

## 1. Project idea (what you're building and why)

**The pitch:** A factory has machines that continuously emit sensor readings
(temperature, torque, rotational speed, tool wear). Instead of waiting for a
machine to break, this system predicts the probability that a machine will
fail *before* it does, explains *why* it thinks so, and shows it all on a
dashboard a maintenance manager could actually use.

```
Sensor readings → ML model → Failure probability (%) → Explanation (SHAP) → Alert
```

**Why this project is a good portfolio piece:**
- It maps directly to your Lear Corporation internship (industrial data,
  pipelines, dashboards, Palantir) — a recruiter can connect the dots instantly.
- It's not just a notebook — it's structured like production code: ingestion,
  preprocessing, feature engineering, training, an API, and a UI.
- It touches the full ML lifecycle: data engineering → modeling → explainability
  → deployment → MLOps. That breadth is exactly what junior DS/ML job
  descriptions ask for.

**Dataset:** AI4I 2020 Predictive Maintenance Dataset (UCI Machine Learning
Repository, also mirrored on Kaggle). ~10,000 rows, realistic industrial
sensor features, binary failure label plus 5 failure-mode sub-labels.

## 3. Where to create the folder

- **Location:** a plain local path outside any cloud-synced folder — i.e. NOT
  inside Google Drive, OneDrive, or Dropbox folders. Those sync tools lock
  files mid-write and cause weird Git errors.
  - macOS/Linux: `~/Projects/predictive-maintenance`
  - Windows: `C:\Users\<you>\Projects\predictive-maintenance`
- **No spaces or accents in the path** — keeps every tool (Docker, some shells)
  happy.
- This will become the root of your Git repo and your GitHub repo — one folder,
  one repo, one project.

## 5. Exact steps, in order

### Step 0 — Install prerequisites (once)
- Python 3.10+ (`python --version`)
- Git (`git --version`)
- A GitHub account
- Optional: VS Code, Docker Desktop

### Step 1 — Create the folder and initialize Git *first*
Doing this before adding files means every phase below can be its own commit —
useful history, and easy to resume from any point.
```bash
mkdir -p ~/Projects/predictive-maintenance
cd ~/Projects/predictive-maintenance
git init
```
Create `.gitignore`:
```
venv/
__pycache__/
*.pyc
data/processed/
mlruns/
.env
```
```bash
git add .gitignore
git commit -m "Initial commit: gitignore"
```

### Step 2 — Create the folder skeleton
```bash
mkdir -p data/raw data/processed notebooks src models mlruns api dashboard tests config
```

### Step 3 — Virtual environment + requirements
```bash
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
```
Add the `requirements.txt` (content above) into the root, then:
```bash
pip install -r requirements.txt
git add requirements.txt
git commit -m "Add requirements.txt"
```

### Step 4 — Get the dataset
Download the AI4I 2020 dataset (Kaggle or UCI) into `data/raw/ai4i2020.csv`.
Leave it out of `.gitignore` — it's small enough (~1MB) to commit, and makes
the repo runnable for anyone who clones it.
```bash
git add data/raw/ai4i2020.csv
git commit -m "Add raw dataset"
```

### Step 5 — Data pipeline scripts
Add `src/ingestion.py`, `src/preprocessing.py`, `src/feature_engineering.py`
(all three already written and fixed — the column-naming bug between the
space/bracket names like `'Air temperature [K]'` and the snake_case names like
`'Air_temperature_K'` is resolved in `preprocessing.py`, which now renames
columns once so every script downstream agrees).
Run them in order:
```bash
python src/ingestion.py
python src/preprocessing.py
python src/feature_engineering.py
```
```bash
git add src/ingestion.py src/preprocessing.py src/feature_engineering.py
git commit -m "Add data pipeline: ingestion, preprocessing, feature engineering"
```

### Step 6 — EDA notebook
Create `notebooks/01_EDA.ipynb`. Explore distributions, correlations, class
imbalance, failure rate. Save a couple of plots as PNGs for the README later.
```bash

git commit -m "Add exploratory data analysis notebook"
```

### Step 7 — Train models

`models/model_comparison.csv`).

```bash
git add src/train.py models/best_model.joblib models/scaler.joblib models/model_comparison.csv
git commit -m "Add training script and trained model"
```

### Step 8 — Explainability
